6.828 2011 第 19 讲：虚拟机

阅读：x86 虚拟化的软件和硬件技术比较，Keith Adams 和 Ole Agesen，ASPLOS 2006。

什么是虚拟机？
计算机的模拟作为主机计算机上的应用程序运行
准确
隔离
快速

为什么要使用虚拟机？
一台计算机，多个操作系统（OSX 和 Windows）
管理大型机器（以操作系统粒度分配 CPU/内存）
内核开发环境（像 qemu）
更好的故障隔离：包含入侵

我们需要多准确？
处理操作系统内核的奇怪特性
精确重现错误
处理恶意软件
不能让客户突破虚拟机！
通常目标：客户无法区分虚拟机和真实计算机是不可能的
客户无法逃离其虚拟机
一些虚拟机妥协，需要客户内核修改

虚拟机是一个古老的想法
1960 年代：IBM 使用虚拟机来共享大型机器
1990 年代：VMWare 重新普及了虚拟机，用于 x86 硬件

术语
[图：硬件，VMM，虚拟机..]
VMM（"主机"）
客户：内核，用户程序
VMM 可能在主机操作系统中运行，例如 OSX
或者 VMM 可能是独立的

VMM 职责
在客户之间分配内存
在客户之间时间共享 CPU
模拟每个客户的虚拟磁盘、网络
实际上是真实磁盘的一部分

为什么不模拟？
VMM 解释每个客户指令
为客户维护虚拟机状态
eflags, %cr3 等
太慢了！

想法：尽可能在真实 CPU 上执行客户指令
对大多数指令有效
例如 add %eax, %ebx

如何防止客户执行特权指令？
否则会破坏 VMM、其他客户等
想法：以 CPL=3 运行每个客户内核
普通指令正常工作
特权指令将（通常）陷阱到 VMM
VMM 可以将特权操作应用于*虚拟*状态
而不是真实硬件
"陷阱并模拟"

陷阱并模拟示例 -- CLI / STI
VMM 为客户维护虚拟 IF
VMM 控制硬件 IF
可能在客户运行时保持中断启用
即使客户使用 CLI 禁用它们
VMM 查看虚拟 IF 来决定何时中断客户
当客户执行 CLI 或 STI 时：
保护违规，因为客户在 CPL=3
硬件陷阱到 VMM
VMM 查看*虚拟*CPL
如果是 0，改变*虚拟*IF
如果不是 0，模拟保护陷阱到客户内核
VMM 必须使客户只看到虚拟 IF
并完全隐藏/保护真实 IF

x86 上的陷阱并模拟很困难
并非所有特权指令在 CPL=3 都会陷阱
popf 静默忽略对中断标志的更改
pushf 显示*真实*中断标志
所有这些陷阱可能很慢
VMM 必须看到 PTE 写入，这些不使用特权指令

我们必须隐藏什么真实 x86 状态（即!=虚拟状态）？
CPL（CS 的低位），因为它为 3，客户期望为 0
gdt 描述符（DPL 3，不是 0）
gdtr（指向影子 gdt）
idt 描述符（陷阱到 VMM，不是客户内核）
idtr
页表（不映射到期望的物理地址）
%cr3（指向影子页表）
IF 在 EFLAGS 中
%cr0 等

VMM 如何给客户内核专用物理内存的错觉？
客户想要从 PA=0 开始，使用所有"安装的"DRAM
VMM 必须支持许多客户，它们不能都真正使用 PA=0
VMM 必须保护一个客户的内存免受其他客户侵害

想法：声明 DRAM 大小小于真实 DRAM
确保启用了分页
维护客户页表的"影子"副本
影子将 VA 映射到与客户不同的 PA
真实%cr3 引用影子页表
虚拟%cr3 引用客户的页表

示例：VMM 为客户物理内存 0x1000000 到 0x2000000 分配
如果客户更改%cr3，VMM 会得到陷阱（因为客户内核在 CPL=3）
VMM 将客户的页表复制到"影子"页表
VMM 在影子表中每个 PA 添加 0x1000000
VMM 检查每个 PA < 0x2000000

为什么 VMM 不能就地修改客户的页表？
也影子 GDT、IDT
真实 IDT 引用 VMM 的陷阱入口点
如果需要，VMM 可以转发到客户内核
VMM 也可能伪造来自虚拟磁盘的中断
真实 GDT 允许 CPL=3 执行客户内核
注意我们依赖硬件陷阱到 VMM 如果客户写入%cr3、gdtr 等

我们也需要陷阱如果客户*读取*吗？
所有读/写敏感状态的指令都会在 CPL=3 造成陷阱吗？
push %cs 将显示 CPL=3，不是 0
sgdt 显示真实 GDTR
pushf 推送真实 IF
假设客户关闭了 IF
VMM 将保持真实 IF 开启，只是推迟中断到客户
popf 在 CPL=3 时忽略 IF，无陷阱
所以 VMM 不知道客户内核是否想要中断
IRET：无环变化所以不会恢复 SS/ESP

我们如何应对揭示真实状态的非陷阱指令？
修改客户代码，将它们更改为 INT 3，这会造成陷阱
跟踪原始指令，在 VMM 中模拟
INT 3 是一个字节，所以不改变代码大小/布局
这是论文二进制翻译的简化版本

重写器如何知道指令边界？
或者字节是代码还是数据？
VMM 可以查看符号表获取函数入口点吗？

想法：只扫描已执行的部分，因为执行揭示了指令边界
原始内核开始（编造这些指令）：
entry: pushl %ebp ...
popf ...
jnz x ...
jxx y
x: ...
jxx z

当 VMM 首次加载客户内核时，从入口重写到第一个跳转
用 int3 替换坏指令（popf）
用 int3 替换跳转
然后在 int3 陷阱到 VMM 时启动客户内核
查看跳转可能去哪里（现在我们知道边界）
对于每个分支，再次 xlate 直到第一个跳转
用原始分支替换 int3
重新启动
跟踪我们已重写的内容，所以不会重复

间接调用/跳转？
相同，但不能用原始跳转替换 int3
因为我们不确定下次地址是否相同
所以每次都必须陷阱

ret（函数返回）？
==通过栈上的指针间接跳转
不能假设栈上的 ret PC 来自调用
所以每次都必须陷阱。慢！

如果客户读取或写入自己的代码怎么办？
不能让客户看到 int3
必须重新重写客户修改的任何代码

我们可以使用页面保护来陷阱和模拟读/写吗？
不可以：不能为 X 设置 PTE 但没有 R
也许使 CS != DS
将重写代码放在 CS 中
将原始代码放在 DS 中
写保护原始代码页面
在写入时陷阱模拟写入
如果已重写则重新重写

我们需要重写客户用户级代码吗？
技术上是：SGDT, IF
但实际上可能不需要
用户代码只做 INT，这会陷阱到 VMM

如何处理页表？
记住 VMM 保持影子页表，在 PTE 中有不同的 PA
扫描整个页表在每次%cr3 加载时？
创建影子页表

如果客户经常写入%cr3，在上下文切换期间？
想法：影子页表的延迟填充
以空影子页表开始（只有 VMM 映射）
所以客户在加载%cr3 后会产生许多页面错误
VMM 页面错误处理程序只将需要的 PTE 复制到影子页表
重新启动客户，无客户可见的页面错误

如果客户经常在一组页表之间切换怎么办？
因为它在运行过程中上下文切换
可能不修改它们，所以重新扫描（或延迟错误）浪费
想法：VMM 可以缓存多个影子页表
缓存由客户页表地址索引
在客户%cr3 写入时预填充页表
会使上下文切换快得多

如果客户内核写入 PTE 怎么办？
存储指令不是特权的，无陷阱
VMM 需要知道这个写入吗？
是的，如果 VMM 缓存多个页表
想法：VMM 可以写保护客户的 PTE 页面
在 PTE 写入时陷阱，模拟，也在影子页表中
这是论文讨论的三方权衡
跟踪成本/隐藏页面错误/上下文切换成本
减少一个需要更多其他两个
而这三个都很昂贵

如何保护客户内核免受客户程序写入？
都在 CPL=3
在 IRET 时删除内核 PTE，INT 时重新安装？

如何处理设备？
陷阱 INB 和 OUTB
DMA 地址是物理的，VMM 必须转换和检查
很少有客户使用真实设备的意义
想要与其他客户共享
每个客户获得磁盘的一部分
每个客户看起来像是不同的 Internet 主机
每个客户获得一个 X 窗口
VMM 可能模仿一些标准的以太网或磁盘控制器
不管主机计算机上的实际硬件
或者客户可能运行特殊驱动程序跳转到 VMM

今天的论文
两个大问题：
如何应对揭示特权状态的指令？
例如 pushf，查看%cs 的低位
如何避免昂贵的陷阱？

VMware 的答案：二进制翻译（BT）
用做正确事情的代码替换违规指令
代码必须能够访问 VMM 的虚拟状态
BT 示例使用：
CLI/STI/pushf/popf -- 读/写虚拟 IF
检测修改 PTE 的内存存储
写保护页面，第一次陷阱，然后重写
新序列同时修改影子页表和真实页表

如何隐藏客户代码的 VMM 状态？
因为非特权 BT 代码现在读/写 VMM 状态
将 VMM 状态放在非常高内存中
使用段限制防止客户使用最后几页
但设置%gs 允许 BT 代码访问这些页面

BT 挑战
难以找到指令边界，指令 vs 数据
翻译代码是不同大小
因此代码指针不同
程序期望在栈上看到原始函数指针，返回 PC
翻译代码必须在使用前映射
因此每个 RET 需要在 VMM 状态中查找

Intel/AMD硬件支持虚拟机使实现合理性能的VMM容易得多
硬件本身直接维护每个客户的虚拟状态
CS（带 CPL），EFLAGS，idtr 等
硬件知道自己在"客户模式"
指令直接修改虚拟状态
避免大量陷阱到 VMM
硬件基本上添加了一个新的特权级别
VMM 模式，CPL=0，...，CPL=3
客户模式 CPL=0 不是完全特权的
系统调用时无陷阱到 VMM
硬件处理 CPL 转换

内存、页表呢？
硬件支持*两个*页表
客户页表
VMM 的页表
客户内存引用经过双重查找
客户页表中的每个物理地址通过 VMM 的页表转换
因此客户可以直接修改其页表而 VMM 不必影子它
无需 VMM 写保护客户页表
无需 VMM 跟踪%cr3 更改
VMM 可以确保客户只使用自己的内存
只在 VMM 页表中映射客户的内存
