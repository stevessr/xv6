Rarayanan 等人"RedLeaf：安全操作系统的隔离和通信"的常见问题

Q: Linux 社区将 Rust 适应的努力与这篇论文有何关系？
A: Linux 社区有很多工作将 Rust 用作 C 的替代品，这本身并不容易；例如，参见 https://www.usenix.org/publications/loginonline/empirical-study-rust-linux-success-dissatisfaction-and-compromise。论文探讨了一个不同的问题：我们能否设计一个使用语言隔离而不是硬件隔离（即页表、用户/内核模式等）的操作系统？论文的想法是否会在长期产生影响现在还不清楚。

Q: 我很难理解这些抽象如何与现有内存管理硬件交互。它有一个页表，页面是如何管理的？
A: RedLeaf 不使用页表、用户/内核模式等。它的隔离基于语言级类型安全和内存管理。

Q: 什么是域？
A: 隔离的单位，就像进程是 xv6 中隔离的单位一样。

Q: 透明驱动程序恢复是否适用于任何设备？
A: RedLeaf 的驱动程序恢复适用于像网络驱动程序这样的无状态驱动程序。透明恢复写入持久存储的驱动程序很难透明完成，除非使用驱动程序的存储系统遵循日志等崩溃安全纪律。

Q: 什么是零拷贝通信？
A: 一个性能目标，归结为一个域调用另一个域中的方法时避免复制参数。如果一个域向另一个域传递大缓冲区，复制该缓冲区代价昂贵。通过将缓冲区存储在 RedLeaf 的共享堆中，可以避免此复制，因为域只需将缓冲区的引用传递给另一个域，这导致零拷贝。

Q: 什么是"迁移线程"？
A: 在 xv6 中，线程之间发生通信：一个线程通过管道发送数据，另一个线程接收数据。在 RedLeaf 中，发送线程进入（迁移到）接收域并运行被调用的方法。

Q: Rust 有哪些特性或限制，使其比 C 和其他编程语言安全得多内存？
A: 它不允许像 C 中那样的任意类型转换。它强制执行所有权规则，这允许 Rust 编译器对对象的生命周期进行静态分析并释放它们；在 C 中，开发者负责释放内存。这避免了 C 开发人员犯的大量错误。所有权规则对如何编写程序施加了限制，从 C 切换到 Rust 并不简单。

Q: Rust 中的线性类型是什么？
A: 此参考是很好的起点：https://doc.rust-lang.org/book/ch04-00-understanding-ownership.html

Q: Rust 如何在没有垃圾收集器的情况下管理资源/内存？
A: 通过所有权规则，这允许 Rust 编译器对对象的生命周期进行静态分析并释放它们。

Q: 还有什么其他语言被考虑用于开发操作系统。是否有人用 Python 编写过操作系统，它的性能如何？
A: 解释型语言如 Python 通常不适合内核，因为解释有显著的运行时开销。Rust 的替代品是 Java，它曾流行于系统编程，但它使用垃圾收集器进行内存管理，这很难与内核良好配合（因为内核实际上不能容忍 GC 暂停）。这篇论文提供了对使用基于 GC 语言（Go）编写内核的 GC 开销的详细分析：https://www.usenix.org/conference/osdi18/presentation/cutler

Q: RedLeaf 如何确保跨域调用遵循交换规则？
A: RedLeaf 定义了一个接口定义语言来调用其他域中的方法。语言设计成这样，IDL 编译器可以检查传递给域的参数类型是否可交换。第 3.1.5 节的最后一段概述了静态检查的内容。

Q: 为什么创建 Rv6 而不是在 RedLeaf 之上运行现有操作系统如 Linux？
A: 作者想要探索细粒度隔离域的成本和收益。作为测试用例，他们将 rv6 分成几个子域，而不是在 RedLeaf 之上将现有操作系统作为单个域运行。

Q: RedLeaf 信任"使用不安全代码的 Rust 核心库"是否安全？
A: Rust 核心库使用 Rust unsafe 来跳出类型系统的限制。这在原则上会破坏 RedLeaf 保证，但作者假设核心库的 Rust 开发人员知道他们在做什么，没有引入错误。

Q: 安全/高级语言有哪些特征？
A: 关键属性是类型安全/内存安全和自动内存管理。

Q: RedLeaf 如何处理跨域通信，当传递复杂数据结构时？
A: RedLeaf 通过传递 RRef 按引用传递此类数据结构，RRef 可以指向共享堆上的其他对象，因此 RedLeaf 可以通过只传递树根跨域传输复杂的树状数据结构。

Q: "线程展开"做什么？
A: 当线程恐慌时，恐慌时的状态（即 pc、sp 和其他寄存器）可能不允许线程继续运行并返回错误。展开将状态恢复到线程调用恐慌方法时的状态，确保线程可以继续并返回错误。

Q: RedLeaf 是否能够防止 Spectre/Meltdown 攻击？
A: 不。作者"推测"未来的 CPU 修复（和 Rust 改进）将使这对 RedLeaf 来说不是问题。

Q: 什么是代理，它的作用是什么？
A: 代理是 RedLeaf IDL 编译器生成的 Rust 代码片段。代理帮助将调用域与被调用域的恐慌隔离，并允许通过共享堆按引用传递大参数（参见图 2）。要调用另一个域中的方法，域调用代理方法，代理做一些记账（例如，更改按引用传递的参数的所有权，检查目标域没有崩溃，创建延续而不是在目标域中线程恐慌等），然后调用目标域中的方法。
