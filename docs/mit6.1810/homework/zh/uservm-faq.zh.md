Appel & Li 论文"用户程序的虚拟内存原语"的常见问题

Q: 垃圾收集器与操作系统的关系是什么？

A: 没有直接关系。垃圾收集器是语言运行时的一部分
（例如，Python 或 Go 运行时）。Python 解释器，例如，
作为用户程序在内核之上运行，而解释器的一个
组件是垃圾收集器。与 C 不同，
在这些语言中，开发人员不必调用 malloc/free 来
管理内存，而是由语言垃圾收集器为
开发人员管理内存。这避免了许多常见的编程错误，如
重复释放，使用已释放后的内存等。

Q: Python 使用什么 GC 算法？

A: Cpython，一个常见的 python 解释器使用几种不同的垃圾
收集器实现（参见
https://github.com/python/cpython/blob/main/InternalDocs/garbage_collector.md)。
其中一个是分代的。

Q: 页面错误在流水线处理器上是否正确工作？

A: 今天的 CPU 提供所谓的"精确"中断，这
保证保存的进程状态对应于一个顺序 CPU
在开始下一条指令之前先完成一条指令。
在流水线处理器中实现精确中断是
非平凡的。

Q: 谁来跟踪页面是否被修改？

A: 硬件通常跟踪页面是否被
写入（被修改）。例如，RISC-V 在 PTE 中维护了脏位
（参见 xv6 教材中的图 3-2）。然而，许多操作系统
不让用户应用程序看到该位；论文认为
这是很遗憾的，因为用户应用程序可以从
中受益。

Q: VM 的数据页压缩算法在实践中使用吗？

A: 查看 https://en.wikipedia.org/wiki/Virtual_memory_compression
了解发展历史和最新用法，包括 Android
(https://developer.android.com/topic/performance/memory-management)，
它使用 Linux 的 zram。

Q: 是否可以将并发和分代垃圾收集结合起来？

A: 是的，请参见例如：https://dl.acm.org/doi/pdf/10.1145/96709.96735

Q: 为什么 xv6 不支持用户 VM 原语？我们如何
添加这个功能？

A: 因为 xv6 的目标是成为一个最小的教育操作系统。然而，
你将在 mmap 实验中实现一些用户级 VM 原语。

Q: 随着闪存的发展，关于磁盘局部性（和论文中的一些
其他假设）的信息的相关性如何？

A: 不太相关。对闪存的访问时间比对
磁性磁盘要低得多。然而，闪存仍然比 RAM 慢几个数量级，
所以这仍然很重要。

Q: 在跨平台兼容性与
专门针对 Prot1 与 ProtN 等事物的用户级算法之间是否有权衡？
或者现代程序是否为每个平台编写单独的低级代码，或者
现代操作系统都实现类似的原语集合？

A: 现代操作系统实现类似的原语集合；查看 mmap，
munmap, sigaction，和相关的系统调用（例如，运行"man mmap"
在命令行上）。

Q: 检查点多久发生一次？每次线程需要
写入内存时，操作系统是否必须通过保存
程序的可写主内存空间并重启所有线程来检查点：

A: 由应用程序选择检查点的频率
——每次写入都检查点没有意义，因为这
成本太高；你应该考虑以许多分钟为时间
框架。例如，你可能希望定期检查点一个长时间运行的计算
应用程序，这样如果计算机崩溃，你不必从头开始。

Q: 在数据压缩分页方案中，数据是如何
确切地被压缩和解压缩的？

A: 使用压缩算法。zram（见上文）使用 zstd
(https://en.wikipedia.org/wiki/Zstd)。

Q: 我也不清楚在 32 位和 64 位地址之间转换指针以扩展
可寻址性的直觉。

A: 鉴于现在大多数 CPU 上的指针都是 64 位，这个例子有点深奥。

Q: 变异器和收集器究竟是什么？

A: 这是垃圾收集器术语：变异器是应用程序
程序（比如 Python 程序），它有对象并读/写它们，
而收集器是运行时中进行垃圾
收集的组件。

Q: 当用户模式可以指定故障处理程序时，
操作系统如何保证安全性？

A: 内核将页面错误转发给经历
错误的进程。因此，进程只看到自己的页面错误，并且可以
只修改自己的地址空间。如果处理程序有错误，那么
进程可能会崩溃，但只有那个进程会崩溃。

Q: 何时使用持久存储？

A: 文件系统是持久存储的一个例子。论文中的持久
存储将持久性扩展到正在运行的程序的对象，
因此开发人员不必显式地持久化
对象（即，调用文件系统调用）。目前不太
流行这个想法，但某些系统提供它。

Q: 虚拟内存技术目前对数据库实现有多少影响？

A: 数据库通常使用 mmap 将数据库文件映射到数据库
服务器的地址空间，以便数据库可以依赖 OS
页面缓存来缓存文件的块（而不是必须
实现自己的缓冲区缓存并可能遭受双重
缓冲）。对于使用 mmap 进行数据库有一些有趣的批评；
例如，参见 https://db.cs.cmu.edu/mmap-cidr2022/。

Q: 在崩溃的情况下，尚未保存到磁盘的持久存储
如何恢复？

A: 通常它们支持事务以原子方式更新
一组对象。事务系统通常使用日志记录。从
今天的论文角度来看，崩溃安全性是一个正交问题。
