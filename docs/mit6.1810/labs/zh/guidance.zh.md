# 实验指导

## 作业难度

每个作业都会标明难度：

  * 简单：不到一小时。这些练习通常是对后续练习的热身练习。

  * 中等：1-2 小时。

  * 困难：超过 2 小时。通常这些练习不需要太多代码，但代码很难正确实现。

这些时间是我们预期的粗略估计。对于一些选做作业，我们没有解决方案，难度只是一个猜测。如果你发现自己在某个作业上花费的时间超过我们的预期，请在 piazza 上联系或来答疑。

总的来说，练习通常不需要太多代码行（几十行到几百行），但代码在概念上很复杂，细节往往很重要。所以，请确保你完成了实验的指定阅读，通读相关文件，查阅文档（RISC-V 手册等在[参考页面](reference.html)上），然后再写任何代码。分小步骤实现你的解决方案（作业通常建议如何分解问题），并在继续下一步之前测试每个步骤是否有效。

警告：不要在实验截止前一晚开始；将其分散在多天更节省时间。操作系统内核中的错误表现可能令人困惑，可能需要大量思考和仔细调试来理解和修复。

## 调试技巧

以下是一些调试技巧：

  * 确保你理解 C 和指针。Kernighan 和 Ritchie 的"《C 程序设计语言》（第二版）"是对 C 的简洁描述。看看这个示例[代码](https://pdos.csail.mit.edu/6.828/2019/lec/pointers.c)并确保你理解为什么它会产生这样的结果。

以下是一些特别值得记住的常见指针习语：
    * 如果`int *p = (int*)100`，那么`(int)p + 1`和`(int)(p + 1)`是不同的数字：第一个是`101`但第二个是`104`。当向指针添加整数时，如第二个情况，整数会被隐式乘以指针指向对象的大小。
    * `p[i]`被定义为与`*(p+i)`相同，引用 p 指向的内存中的第 i 个对象。上述加法规则有助于此定义在对象大于一个字节时正常工作。
    * `&p[i]`与`(p+i)`相同，产生 p 指向内存中第 i 个对象的地址。

尽管大多数 C 程序永远不需要在指针和整数之间转换，操作系统经常这样做。每当您看到涉及内存地址的加法时，请问自己这是整数加法还是指针加法，并确保要添加的值被适当地乘或不乘。

  * 如果你有一个部分工作的练习，请通过提交代码来检查点你的进度。如果你以后破坏了某些东西，那么你可以回滚到检查点并以更小的步骤前进。要了解更多关于 Git 的信息，请看看[Git 用户手册](http://www.kernel.org/pub/software/scm/git/docs/user-manual.html)，或这个[面向计算机科学的 Git 概述](http://eagain.net/articles/git-for-computer-scientists/)。

  * 如果你的代码失败了一个测试，请确保你理解为什么。插入打印语句直到你理解发生了什么。

  * 你可能会发现你的打印语句产生了大量你想搜索的输出；一种方法是在`script`中运行`make qemu`（在你的机器上运行`man script`），这会将所有控制台输出记录到一个文件，然后你可以搜索。不要忘记退出`script`。

  * 打印语句通常是一个足够强大的调试工具，但有时能够单步执行一些汇编代码或检查堆栈上的变量是有帮助的。要使用 gdb 与 xv6，在一个窗口中运行`make qemu-gdb`，在另一个窗口中运行`gdb-multiarch`（或`riscv64-linux-gnu-gdb`或`riscv64-unknown-elf-gdb`）（如果你使用 Athena，请确保两个窗口都在同一 Athena 机器上），设置断点，然后是'c'（继续），xv6 将在击中断点时运行。参见[使用 GNU 调试器](https://pdos.csail.mit.edu/6.828/2019/lec/gdb_slides.pdf)以获取有帮助的 GDB 技巧。（如果你启动 gdb 并看到类似'warning: File ".../.gdbinit" auto-loading has been declined'的警告，编辑~/.gdbinit 以添加"add-auto-load-safe-path..."，如警告所建议的那样。）

  * 如果你想看看编译器为 xv6 内核生成的汇编代码，或找出特定内核地址处的指令，参见文件`kernel/kernel.asm`，这是 Makefile 在编译内核时生成的。（Makefile 还为所有用户程序生成.asm。）

  * 如果内核导致意外故障（例如使用无效内存地址），它将打印包含程序计数器（"sepc"）的错误消息，该计数器是在崩溃时的值；你可以搜索`kernel.asm`以找到包含该程序计数器的函数，或者你可以运行`addr2line -e kernel/kernel _pc-value_`（运行`man addr2line`了解详情）。如果你想要回溯，使用 gdb 重启：在一个窗口中运行'make qemu-gdb'，在另一个窗口中运行 gdb（或 riscv64-linux-gnu-gdb），在 panic 处设置断点（'b panic'），然后是'c'（继续）。当内核击中断点时，键入'bt'以获取回溯。

  * 如果你的内核挂起，可能是由于死锁，你可以使用 gdb 找出它在哪里挂起。在一个窗口中运行'make qemu-gdb'，在另一个窗口中运行 gdb（riscv64-linux-gnu-gdb），然后是'c'（继续）。当内核似乎挂起时，在 qemu-gdb 窗口中按 Ctrl-C 并键入'bt'以获取回溯。

  * `qemu`有一个"监视器"，让你查询模拟机器的状态。你可以通过键入 control-a c（"c"表示控制台）来访问它。一个特别有用的监视器命令是`info mem`以打印页表。你可能需要使用`cpu`命令选择哪个核心`info mem`查看，或者你可以使用`make CPUS=1 qemu`启动 qemu 以便只有一个核心。

花时间学习上述提到的工具是非常值得的。
